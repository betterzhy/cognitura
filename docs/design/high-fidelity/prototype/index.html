核心问题

并发写入发生时，读取如何保持一个一致的观察边界？

一致性读不是把数据冻结成静态副本，而是在事务语义、版本链与可见性条件之间， 选择一个稳定且可解释的读取结果。

核心结论

Read View 定义可见范围，版本链提供候选版本。

两者共同决定当前事务能看见哪一个记录版本。隔离级别改变 Read View 的创建时机， 当前读则绕过快照语义，因此边界必须在正文中直接说明，而不能藏在图或面板里。

CoreQuestion · 核心问题

一次一致性读，如何从多个记录版本中选出当前事务真正可见的那个？

CoreConclusion · 核心结论

Read View 划定可见边界，版本链提供候选，判断规则完成选择。

三者缺一不可：快照只描述边界，版本链只保存历史，最终结果来自二者在隔离语义下的共同作用。

一致性读面对的不是“有没有旧版本”，而是“哪个版本对当前事务成立”。读取先建立观察边界， 再检查记录版本是否位于边界内；若当前版本不可见，就沿 Undo 版本链向过去回溯，直到找到 第一个满足可见性条件的候选。这个顺序把观察范围、历史候选与选择规则连接成连续机制。

在可重复读中，同一事务通常复用观察边界，因此两次查询可以保持一致；在读已提交中，新的语句可建立 新边界，结果可能随已提交版本前进。这里的关键 Relation 是：隔离级别决定 Read View 的创建时机， Read View 又约束版本可见性；它们不是并列标签，而是机制闭环中的因果连接。
